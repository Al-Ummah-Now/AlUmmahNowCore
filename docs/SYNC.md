# Sync (`aun-sync`)

Cross-device state for the native apps: watch position and history, timestamped notes and
bookmarks, Watch later, likes, and the device-local offline library (download records).

## Model

The user's replicated state (`SyncState`) is a set of **last-writer-wins registers** (`Lww<T>`),
each stamped `(ts_ms, device)`:

| State | Registers |
|---|---|
| Watch state per video | `position_ms`, `duration_ms`, `completed`, `removed` (tombstone) |
| History | `history_cleared` tombstone: entries whose latest activity is older are hidden |
| Notes / bookmarks | `text` (empty = bookmark), `position_ms`, `removed`; id generated by the client |
| Watch later | membership per video (`false` = tombstone), `saved_order` |
| Likes | membership per video |
| Metadata | title / thumbnail / channel cache per video |

`join` merges per register (the newer stamp wins; on equal stamps the serialized value decides).
That makes it commutative, associative and idempotent, so replicas converge whatever order the
updates arrive in. `tests/merge_props.rs` checks this on random multi-device histories.

Local writes use a **Lamport floor**: each one is stamped `max(now, highest stamp seen + 1)`. A
stamp from the server's clock, or from a peer whose clock is ahead, therefore cannot hide a later
local edit.

A video is in history when its latest activity (position or completed) is newer than both its
`removed` tombstone and `history_cleared`. Watching again brings a removed entry back.

## Engine

`SyncEngine` (one per signed-in account) holds the state, an **outbox** of server writes and the
download records. It persists everything to one JSON file, replaced atomically (temp file, then
rename). A corrupt file is moved to `<file>.corrupt` and the engine starts empty.
While open, the engine holds an exclusive OS lock on `<file>.lock` (`flock` / `LockFileEx`, released
when the engine is dropped or the process exits). A second engine on the same file, in another
process or the same one, fails with `Conflict` instead of loading the same state and overwriting
the other's writes; apps should show "already open in another window" and not retry in a loop.

- **Debounced positions.** `record_position` updates local state at once. The server write is
  queued with a due time of `last push + position_push_interval_ms` (default 30 s) and coalesced
  per video, so a player reporting every second costs about one request per 30 s. Call `flush()`
  on pause, background or exit to push regardless.
- **Outbox order.** Clears, then removals, then progress, then library changes. A removal also
  drops that video's queued progress, so the removal is not undone.
- **Errors.** Retryable failures (network, offline, 408/425/429/5xx) and 401/403 keep the write
  and return the error, so the app can retry later or after re-auth. Other 4xx drop the write,
  which is counted in `SyncReport::dropped`.
- **Pull.** `sync()` pushes due writes, then pulls history (up to `history_pages` ×
  `history_page_size`), Watch later and likes:
  - Server history entries are merged with the server's `lastWatchedAt` as the stamp. A video with
    an unpushed local position keeps the local value until that write lands.
  - When the history listing completed within the page budget, entries the server no longer lists
    are tombstoned (unless they have a pending write or newer local activity).
  - Library membership is reconciled the same way, using a pull-time server stamp.
- **Queries.** `history(limit, offset)`, `continue_watching(limit)` (position ≥ 30 s, not
  completed (< 95 %), newest first), `notes_for_video`, `saved_items` (newest additions on top,
  then the user's order) and `liked_items`.
- **Notes** have no server endpoint yet. They replicate through `export_state` / `merge_remote`
  (for example over a future endpoint or a device-to-device channel).
- **Listeners.** `SyncListener::on_changed(Vec<SyncChange>)` fires after each change. It is called
  without holding the engine lock, so a listener can call back into the engine.

## Server gaps (Epic 9.9, issue #13)

| Gap | Client workaround today |
|---|---|
| Progress writes are stamped with server time; no client timestamp or LWW | The pull ignores server positions for videos with an unpushed write. A late offline write can still beat a newer write from another device. |
| No tombstones or change feed | Removals are inferred from a *complete* history or library listing. With more history than the page budget, a removal on another device is not seen. |
| No notes / bookmarks endpoint | Kept on-device and replicated by state exchange only. |
| No continue-watching endpoint | Derived from pulled history. |
| Float seconds on the wire | Converted to and from ms in `ApiSyncTransport`. |
| Watch later / liked lists are untyped in the OpenAPI | `parse_library_page` accepts the common shapes (`items` / `videos` / `data`, `videoId` / `id`). |
| `/progress` returns 404 for a video with no history entry | Falls back to `POST /api/watch-history` (record view). |
| History paused server-side gives no signal | Writes are queued and pushed as usual. |
| Clock skew between server and devices | The Lamport floor protects local edits. Ordering across devices is only as good as the clocks until client stamps exist. |

## FFI surface

- **Stateful.** `SyncEngine` is an `Arc` handle; all methods take `&self`. `flush()` and `sync()`
  are async (tokio); the rest are synchronous and cheap.
- **Records.** `WatchStateView`, `HistoryItem`, `ContinueWatchingItem`, `NoteView`, `LibraryItem`,
  `DownloadRecord` / `DownloadState`, `SyncReport`, `SyncConfig`, `SyncChange`.
- **Native adapters.** `SyncListener` (events) and, optionally, a custom `SyncTransport`. The
  default is `ApiSyncTransport` over `aun_api::ApiClient`.
- **Time.** All times are i64 Unix ms and all positions/durations are u64 ms.
